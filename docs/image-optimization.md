# 构建时图片优化

## 已实施：主题头像

PNG 源文件保留在 `src/assets/images/theme-avatar/`，不再放在会原样复制的 public 目录。`ThemeAvatar.astro` 使用 Astro getImage，最长边 512px、不放大、WebP quality 80、保留 alpha；适合 256 CSS px 的 2 倍像素密度展示。这是有损编码，不承诺像素级一致。

| 图片 | 原 PNG | 构建 WebP |
| --- | ---: | ---: |
| light | 323,680 B | 27,784 B（27.1 KiB） |
| dark | 297,710 B | 26,862 B（26.2 KiB） |
| 合计 | 621,390 B | 54,646 B（53.4 KiB） |

减少 566,744 B（553.5 KiB），约 91.2%。相对远端旧单头像 WebP 27,510 B，现在两张头像净增加 26.5 KiB。页面静态图与粒子读取同一 URL，无额外原图请求。文件内容变化会生成新指纹 URL，换图后按静态站流程重新构建、部署。

Astro 会额外输出导入的原 PNG。`prune-theme-avatar-originals.mjs` 构建钩子只清理：与主题头像源文件名匹配、SHA256 相同、且产物文本内无引用的生成副本；不清理源文件、WebP 变体或其他图库。此次删除两个可由源文件重新生成的产物 PNG，共 621,390 B。测试覆盖有引用保留、内容不同保留、源文件与 WebP 保留、重复运行及缺失源目录。

优化发生在构建阶段，增加编码/扫描工作并利用 Astro 图片缓存；不会在客户端实时转码。下载和部署体积下降，不代表粒子 GPU 运算下降。源图解码尺寸也减小，但粒子纹理仍为 256×256、网格不变。

验证：44 页生产构建成功；三个单元测试通过；实际浏览器读取到两张 512×512 WebP，静态透明边缘和签名正常，切换后恢复静态头像。Astro check 仍为 52 个既有错误，并非全项目类型检查通过。

横幅试算仅验证编码体积，尚未逐张视觉验收，也未替换或上传 CDN。现有横幅地址映射到 img.tonks.top，实施时需要同步 CDN 文件、预加载和本地回退；本地变小不等于 CDN 已更新。

相册扫描器直接使用 public 原图，不能简单把 WebP 放在 PNG/JPG 旁边，否则可能重复收录，还会增大部署体积。缩略图机制应放在单独输出目录并明确图库元数据。保留原图与派生图可以减少页面下载，却可能增加总构建体积；两者需分开评估。

当前 src 本地图片经 ImageWrapper/Astro Image 已有优化，public 和远程 URL 通常直接使用原图，不能统一认为全站都未压缩。部分 .png 文件实际编码是 JPEG，应读取格式而非只看后缀。

不建议盲目转换 SVG、已优化 WebP、动态图、favicon/ICO 和 Live2D 模型图集；它们分别涉及矢量清晰度、重复有损压缩、动画、兼容性或模型引用。对外公布的头像 URL 也应保留兼容路径。保留源文件意味着仓库源素材体积不会因本次优化下降，下降的是部署产物与实际图片请求。
