# 响应式文章列表与相册时间线

状态：相册改动已独立推送 `3fc638a`；本轮分页与布局修复仅在本地，等待用户使用 `pnpm dev` 验收。生产动画对照必须用生产预览，因为开发模式没有启用 Swup。

## 导航原则

页码仍使用真实路由，例如 `/2/?size=12`，由原有 Swup 统一负责预取、退场、DOM 替换、滚动、首页 banner、历史和入场。不再拦截页码运行独立 WAAPI 动画，不再维护第二套 popstate/滚动缓存。

保留原主内容区 200ms 退场、400ms 入场、卡片 50ms 阶梯、列表 0.3s 过渡、标题和封面的 hover。布局指定的分类位移反馈、标题竖条对齐属于刻意的样式调整。

静态路由仍每页8篇，支持搜索引擎和禁用脚本。每个路由携带一个惰性 template，包含该页按8篇和12篇显示时缺少的卡片，两种集合合计最多20张。模板不下载封面，不包含文章全文。移除了 `/post-cards/` 片段请求和独立缓存，避免进场完成后才补卡。

全局 Layout 安装列表控制器。在 Swup `content:replace`、原滚动测量之前同步确定卡片和列数；从文章直接进入列表也走同一流程。初次加载在选择完成前隐藏列表并暂停卡片入场，noscript 恢复静态可见内容。

## 响应式与阅读位置

- 1024px 起主体宽度为 `min(90vw, max(78rem, 60vw))`；侧栏为17.5rem，默认字号下280px。
- 列表容器宽度大于910px时网格使用三列、每页12篇；恰好910px仍为两列。列表及两列默认每页8篇。容器不足672px时网格为一列。
- 显式 `size=8|12` 保持分享、刷新和历史的文章范围一致。因此手机直接打开 `?size=12` 也保留12篇。真实窗口缩放或主动切换布局时再按当前文章重新分组。
- 原来的 `/2/` 等无 size 链接仍按8篇理解。旧的 `?page=2&size=12` 及超出该页长范围的静态路由会规范化到对应真实地址。
- 缩放防抖140ms后同时提交列数和篇数，避免“先两列12篇、再两列8篇”。同一路由保留共同节点；需要改变真实页号时使用原 Swup 的 replace 导航。
- 使用缩放前阅读锚点；用户在缩放或导航期间操作滚轮、触摸、键盘时，不强制恢复旧位置。页底空间不足时按浏览器最大滚动范围约束，不能保证卡片在短页仍有完全相同的屏幕坐标。
- 导航结束刷新锚点；abort 阶段不发起嵌套导航。列表间且视口未变时复用 ResizeObserver 的宽度；文章进入列表仍实际测量。
- 分类因布局切换而隐藏时，焦点转到同卡片可见的分类链接；跨769px断点时缓存最近分类焦点，防止CSS先隐藏控件导致140ms防抖后无法恢复。用户主动点击、触摸或聚焦其他控件会取消恢复；被移出当前页的卡片焦点回退到列表。布局重分后提供读屏播报。

文章阅读页外框最大90rem；2080px视口以上正文从760px/19.2px渐增至约879px/22.2px，维持相近的每行字数。网格分类移到底部标签首位，列表分类在日期之前；六类颜色适配明暗主题。元数据增加间距和图标内边距，过长内容可横向滚动。

相册时间线标题、类型和介绍通栏。宽卡片的横向贴纸与日期/描述共用高度，窄卡片上下排布；有照片墙的宽卡片使用竖向贴纸。入口文案为“纪念留影”，不额外放大封面或覆盖文字。

## 性能边界

新增模板在当前构建中增加约0～3.9KiB gzip HTML/页。实际页码导航沿用原完整HTML请求和hover预取，不增加片段请求、轮询或UI框架。动态卡片继续使用既有点赞、评论、浏览计数初始化和缓存。

控制器合并几何读取与DOM写入；只有列表页滚动事件需要时才安排一次RAF记录阅读位置，无持续动画循环。三列显示12篇比8篇多4张可见卡片，不能声称零CPU/内存开销。

历史“54ms长任务”仅保留了4次翻页中出现一次的汇总，缺少调用栈和阶段，无法追溯具体触发动作。50ms是浏览器长任务的统计阈值，并非54ms整体都是额外阻塞；连续54ms不能绘制时可能错过约3个60Hz刷新机会，也可能延后期间的输入响应。它不能解释此前稳定的动画差异。

本轮带trace的串行Edge对照（第三方统计被屏蔽）中，1280px四次预热后的缓存翻页，本地长任务65/67/73/74ms，线上62/63/71/94ms，处于相近范围。trace主要包含DOM替换阶段的微任务、样式重算和布局。该样本不代表所有硬件、首次资源加载或线上第三方负载，也不支持“零长任务”的承诺。

同轮三列12篇样本为77～80ms；最终完整构建的另一轮三列功能回归记录到95～110ms。不同批次负载和测试条件有差异，不能把某个样本当作固定耗时或声称完全没有性能开销。
