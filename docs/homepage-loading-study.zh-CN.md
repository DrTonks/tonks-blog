# 博客首屏加载优化方案

2026-11-26 · 面向 `blog.tonks.top` 的生产构建和本机 7890 代理环境。

## 决策

| 项目 | 建议实施的改动 | 读者和维护者会感受到什么 |
| --- | --- | --- |
| 左右边缘装饰画 | 桌面只取两张同源无损 WebP，窄屏零请求。让正文和开屏独立于装饰图下载 | 保留原始像素、透明度和指针高亮。极慢网首次快速下滑时，插画可能晚于正文出现 |
| 交互图标 | 将实际用到的 SVG 数据随组件构建，把首页的全局 Iconify 运行时移除 | 搜索、主题、调色盘和移动目录在图标服务超时的情况下也能正常显示。新增图标需要经过构建校验 |
| Google Tag Manager | 将 GTM 做成默认关闭的配置，开启时才生成脚本和 noscript iframe | 当前公开容器的 tags、predicates、rules 都为空。以后在 GTM 后台加标签，需要同时开启站点配置并发布 |
| Microsoft Clarity | 保留，开屏结束、浏览器绘出页面后在空闲任务中启动一次 | 减少与开屏争用资源，保留后续录制和热图。启动前的点击轨迹和立即离站的会话会缺失 |

## 实验方法

在隔离的桌面 Edge 上经 127.0.0.1:7890 读取生产页面，线上 HTML 和本地 dist 首页的 SHA-256 前 12 位均为 `e9769b72df69`。每轮新建浏览器上下文，在浏览器请求层替换本轮指定的响应。基线和对照使用相同的四个 Svelte 组件产物作为输入。记录从导航开始到站点自身 `tonks:initial-loader:done` 的耗时、搜索按钮第一次出现 SVG 的时间、开屏期间的长任务、装饰图片响应和统计脚本开始请求的阶段。拦截写入请求，未验证生产统计入库。

首轮原型使用本地图标包时暴露了三个缺失别名。这一轮未纳入下列对照。复测用线上 SVG 路径替换组件内的图标名，保留现有渲染组件。无损 WebP 在内存中生成。拦截回送节省了部分真实服务器往返，这些数字适合验证依赖关系，实际部署后的耗时取决于缓存、带宽、设备和节点。

| 1440 × 900，逐项变更、正反顺序各一轮 | 开屏结束 | 搜索图标出现在 DOM |
| --- | --- | --- |
| 当前页面 | 3.79–5.24 秒 | 1.20–1.89 秒 |
| 仅更改装饰图 | 2.61–2.64 秒 | 1.15–1.27 秒 |
| 仅本地化图标并移除全局加载器 | 4.94–5.17 秒 | 1.10–1.37 秒 |
| 仅把两个统计脚本移至开屏后 | 3.42–3.60 秒 | 1.32–1.56 秒 |

另一次慢资源实验给指定域名或文件增加 4.2 秒延迟。旧版等待两张 CDN 装饰图时，开屏到 5.69 秒才结束。原型连实际要显示的同源图也延迟时，开屏仍在 2.64 秒结束，当时两张图尚未解码。拖慢所有 Iconify 服务域名后，基线开屏结束再过 250 毫秒，搜索按钮仍未出现 SVG；使用本地 SVG 时约 0.50 秒即出现。单独拖慢统计入口，旧版可以在统计响应之前结束开屏。说明三类资源对读者体验的影响各不相同。

390 像素宽时，现版两张 PNG 和两张 WebP 全部返回 200。原型在该宽度未发起装饰图请求，拖宽到 1440 像素后左右图正常加载。两组窄屏开屏分别为 2.63 和 2.64 秒。移动端收益主要是节省流量。这里使用桌面 Edge 调整视口，手机真机的 CPU、触摸和耗电表现仍需单独验收。

最终组合复测关闭空 GTM，Clarity 在开屏结束后经过两次动画帧并进入空闲任务才开始请求。为同源装饰图响应额外加入 300 毫秒延迟。普通桌面基线开屏 3.22 秒，组合原型两次为 2.74 和 2.79 秒，搜索 SVG 在 0.41 和 0.71 秒时出现。CPU 降速四倍时，基线和原型各测一次，开屏分别为 3.53 和 2.85 秒。用 Enter 打开搜索，从 click 到第二次动画帧两者均约 13 毫秒。这个探针只代表一次键盘操作，不等同于真实访客的 INP。降速时两版开屏期间均记录到九个超过或等于 50 毫秒的任务，最长分别为 209 和 169 毫秒，不能据此将这些任务归因于某个脚本。原型已确认每轮仅在开屏之后发起 Clarity 入口请求。

## 图像与动画

1. 保留 PNG 作为美术源文件。将两张图交给构建链按内容哈希生成无损 WebP，保留原图尺寸 400 × 586 和 400 × 587。两张源文件合计 486,779 字节。旧版还下载两张 CDN WebP 共 83,676 字节，因此实际装饰资源体合计 570,455 字节。无损产物共 323,804 字节，桌面冷加载可少传 246,651 字节，窄屏可少传全部 570,455 字节。以上均不含请求头。
2. CDN WebP 与 PNG 的透明通道相同，但两张图的可见像素分别有 116,984 和 141,177 个发生了颜色变化。本方案采用新生成的无损文件，两张图每个可见 RGB 像素和每个透明度值都与原稿一致。
3. 将资源赋值收敛到一个入口，在宽度达到现有 1024 像素断点时启动低优先级获取，并监听跨断点变化和页面替换。同步处理布局内联脚本与 AmbientBackground 对主题 class 变化的监听，避免窄屏被第二个入口重新赋值。相同一侧的 base 和 hover 使用同一 URL。图像获取失败时仅该侧回退一次，避免全站 CDN 状态被装饰图影响。
4. 从 LoadingScreen 的显式预载列表移除左右图，同时排除通用可见 img 的解码等待。每侧在其图片可用且原有滚动阈值满足时使用原有 300 毫秒渐显。为失败中的图片保留已知尺寸；两种编码都不可用时隐藏该侧。Banner、首批首页贴纸、字体和六边形开屏沿用各自的加载与动画逻辑。
5. 保留两层 DOM。明暗主题、指针径向遮罩、离开时保留最后坐标、粗指针和减少动态效果都依赖现有样式。实测滚动后鼠标移入左侧，基线与原型的宽度均为 432 像素、亮色高亮透明度均为 0.15、暗色均为 0.095。

## 图标

构建机通过现有 pnpm 依赖取得所用图标集。访客只接收当前页面或组件实际引用的 SVG 数据。图标名是作者维护的输入，构建按名称和别名解析、去重，日常写作不需要下载 SVG、编辑全站清单或额外跑同步命令。

- **时间线和内容配置**沿用现有 `icon` 字段。时间线目前只注册 Material Symbols，其他已安装的图标集仍需让对应入口支持。按引用的前缀加载集合，复用同一构建进程中的解析结果。新引入一个未安装的系列时，一次性加入对应的 `@iconify-json/<系列>` 依赖、登记构建入口、检查该系列许可并提交锁文件。普通构建从已安装依赖读取。
- **交互组件**由 Navbar 的 Astro 层解析搜索、主题、调色盘和移动目录各自用到的图标，通过 props 交给现有 Svelte 组件。每个控件的有限状态（亮、暗、跟随系统、选中等）都要覆盖。同一个组件的图标名定义在一处，避免再维护一份扫描清单。静态 Astro 组件继续走原有构建路径。对构建后才由 API 返回的名称，采用该功能支持的有限集合和本地默认图标；新增动态来源时明确其数据约定。
- **首批迁移**以当前 14 个图标作为视觉比对样本。线上别名分别是 `contrast-rounded → contrast`、`wallpaper-outline-rounded → wallpaper-rounded`、`blur-on-rounded → blur-on`。另外三个在当前本地包中存在的名称，其 SVG body 与线上返回值不同。先选定并锁定图库版本；只为仍有差异且需保留原样的图标添加带来源信息的兼容数据。后续升级图库时复查这些例外。首批 14 个解析后的图标数据合计 Brotli 约 2.4 KiB。
- **缺名处理**区分作者省略、编辑失误和运行时未知值。省略时沿用类型默认图标；时间线当前对显式写错的名称也会回退，建议开发预览保留回退并告知条目 ID 和名称，发布构建对仓库里明确填写但无法解析的值报错。在 `pnpm dev` 和 `pnpm ship` 使用同一解析逻辑。

复评实验直接调用项目的时间线解析函数，在内存中为现有数据新增 `material-symbols:flight-takeoff`。确认返回飞机的真实图形，随后再次在另一条记录引用同一名称。本地 Material Symbols 的 icons.json 为 7,669,547 字节；时间线图标字典从 13 项、5,849 字节增加到 14 项、6,158 字节，单独 Brotli 压缩从 1,743 增至 1,828 字节。重复引用后字典大小不变。此测量只覆盖字典；页面 HTML 中的每个可见图标实例和新条目的内容还有各自的开销。

构建时检查每个名称均能解析，名称缺失时给出组件和图标名。保留当前 CSS 类、viewBox、currentColor、按钮尺寸、键盘焦点、ARIA 和切换动画。当前 dist 生成的 HTML 未找到实际的 iconify-icon 标签，但源码中仍有 StatCard、TimelineItem 和通用 Icon 包装器。处理这些入口及文章可使用的自定义图标，迁移为构建时解析或仅在确有动态内容时使用同源兼容入口。保留外部服务断网时功能完整的回归用例。实验中已用鼠标和键盘打开搜索，按 Escape 退出，并核实主题菜单中三个选项均有 SVG。

## 统计和运维

读取当前公开 GTM 容器得到 HTTP 200，脚本文本有 334,722 个字符，资源配置里的三个数组为空。此长度为解码文本长度。空容器仍需连接、下载和执行。通过构建变量 `PUBLIC_GTM_ID` 配置容器；留空即关闭。未来启用时，按具体标签配置同意状态与 dataLayer 顺序，首个落地页保留 URL 和来源；Swup 导航的页面浏览只选一个上报来源，避免自动历史跟踪与手工事件重复。

Clarity 直接由博客加载。保留必要的同意状态和轻量命令队列，在开屏结束、至少一次绘制之后用带 1 秒超时的 requestIdleCallback 启动，无该 API 时使用定时任务。对于无开屏或已开屏的页面从就绪状态直接调度，慢开屏为已有的 20 秒资源等待和退场留出余量，22 秒后调度异常兜底。整个文档只初始化一次，遵循已有同意状态，避免 Swup 往返重复录制或在首次按键的同步处理里执行 SDK。浏览器后台对定时器仍可能限速。命令队列无法补回启动前的 DOM 变化、点击或极短会话。

站内文章浏览量通过自己的 API，文章可见累计 5 秒才计数，与 GTM 和 Clarity 独立。验收观察站内浏览量、评论、阅读和导航时，分别验证各自接口。

## 发布验收

- 对同一生产构建做直连与 7890 代理、冷缓存与回访对照。保持主题和视口一致，记录开屏结束、关键图标就绪、实际传输量、LCP、CLS、首次输入至下一帧，以及开屏后最初几秒的长任务。随机 Banner 和贴纸应固定种子或固定选择以便截图比较。用多轮中位数和较慢一组判断，避免一次启动决定结论。
- 桌面验证首页和文章直达、切页、返回首页、亮暗切换、键盘搜索、贴纸拖动、轮播和装饰图快速移入移出。窄屏验证目录、粗指针、横竖屏和 reduced motion。检查 CSS 断点和资源断点一致。验证图片 404 时正文可交互、图标域名不可达时按钮依然完整。
- 对 Clarity 在允许采集的测试环境验证启动一次、快速离站的边界、页面切换和统计入库。将图像、图标和统计分别提交，支持单独回滚并沿用现有 pnpm ship 发布流程。

## 本地实施验收记录

三组改动已在本地生产构建完成。日常新增时间线图标仍只写条目中的 `icon`。现有构建端支持 Material Symbols、MDI、Font Awesome 6 的 brands/regular/solid 及 Simple Icons。新增其他系列时安装对应包并在 `local-icons.server.mjs` 登记前缀。导航的图标定义在 `navbar-icons.server.ts`。作者在 Markdown 中使用的 `<iconify-icon>` 也会在构建时得到内联 SVG，代码示例保留原文。

最终一轮用真实 Edge 打开本地 dist 与线上站点。1440 × 900 下，两站均运行 324 个 400 毫秒的六边形入场动画、324 个 350 毫秒的收拢动画及一次 350 毫秒的遮罩淡出。两次主题切换均触发 560 毫秒的主题揭示动画。搜索、主题菜单及调色盘的取样 SVG 路径与 viewBox 一致，搜索按钮同为 44 × 44 像素。两站均能悬停替换贴纸，从同一篇置顶文章经 Swup 返回后继续显示已加载的贴纸。390 像素宽的文章页验证了移动目录的打开与关闭，以及转宽屏时装饰图的加载。

该轮本地开屏为 2.85 秒，线上为 4.99 秒。本地静态资源从回环地址读取，线上经 7890 代理，且实现验证拦截了统计写入，因此这组数值只用来核对时序。三项独立审查复核了透明像素、单侧失败回退、Markdown 图标、GTM 配置开启后的切页幂等，以及 Clarity 命令排队。第三方统计后台入库需在实际采集环境确认。
