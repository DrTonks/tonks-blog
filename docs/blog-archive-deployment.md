# 博客压缩包发布与提速评估

本轮仅修改博客发布脚本、检查服务器，并在独立临时目录完成测试。**没有运行生产 `pnpm ship`，没有切换线上博客，没有调整 Apache 或 PM2。** 主页的发布脚本保持不变。

## 日常使用

本地确认待发布内容后，仍运行：

```powershell
cd D:\myserver\blogExample
pnpm ship
```

脚本顺序：Astro 构建 → 字体子集 → Pagefind → 本地打包 → 上传压缩包与校验清单 → 服务器校验并解压 → 备份旧站 → 原子交换目录 → 保留当前和上一版归档。

不会再提前清空线上目录。`run-build.mjs` 会打印每个子阶段耗时，部署日志会打印压缩体积、打包、上传、服务端处理及部署总耗时。版本编号规则不变；只有显式 `--bump-version` 才更新站点版本号。

辅助命令：

```powershell
node scripts/deploy.js --check      # 只读检查服务器能力，不上传
node scripts/deploy.js --status     # 只读查看当前版本与中断记录
node scripts/deploy.js --pack-only  # 只在本地打包，打印并保留临时包路径
node scripts/deploy.js --recover    # 恢复中断后的状态记录，不再执行版本切换
node scripts/deploy.js --rollback   # 校验并切换到上一版；再次执行会切换回来
```

`--recover` 和 `--rollback` 会写服务器状态，后者改变线上版本；执行前仍遵循用户的部署许可要求。若发布连接中断，先查看 `--status`，必要时 `--recover`，确认状态后再决定重新发布或回滚。不要将一次连接报错直接等同于切换没有发生。

## 目录与备份

- 线上目录保持 `/var/www/blog`，仍是普通目录，不改为符号链接。
- 私有工作目录为 `/var/www/blog.deploy`，权限 0700，绑定原目录路径和部署用户。
- 已确认成功的版本保存在 `archives/<release UUID>.tar.gz` 和对应 `.manifest.json`，文件权限 0600。成功发布后只保留当前和上一版两套归档。
- 首次使用时自动将现有线上目录制作并校验为上一版备份。以后无需每次重新打包旧站。
- 上传、解压和备份失败时不切换旧站；切换后的状态持久化失败有日志记录，可恢复。
- 只清理脚本管理且归属校验通过的工作目录和过期归档，不清理外部备份或共享表情。
- 归档只含普通文件，不保留空目录，恢复后的站点目录/文件统一为 0755/0644。

这里保存的是静态网站版本，不是 Sleepy 留言数据库备份。S3 发布逻辑保留原顺序，本次优化仅用于当前 SFTP 配置。旧 `cleanRemote`/`CLEAN_REMOTE` 字段不再控制 SFTP 清空行为。

## 服务器检查

2026-09-08 检查确认：Linux 6.8、Python 3.12.3、tar 1.35、gzip 1.12、sha256sum 9.4 均可用，约 30 GiB 剩余空间。博客与临时工作目录可放在同一 ext4 文件系统，SSH 用户具有所需权限。真实 Linux 测试已验证 `renameat2(RENAME_EXCHANGE)` 能交换两个非空目录。

Apache 继续读取 `/var/www/blog`，因此不需要改配置或重载。两站的 `/community/articles.json` Alias 指向 `/var/www/blog/community/articles.json`，解压校验会强制保留该文件及 `.htaccess`、`index.html`、`version.json`。共享 `/emojis/` 仍指向 `/var/www/shared/emojis/`，本流程不更新它。

本地打包使用 Python 标准库 tarfile 和 Node gzip，不新增 npm 依赖。本地需要 Python 3.9+，默认 Windows 使用 `python`，其它系统使用 `python3`；可用 `DEPLOY_PYTHON` 或已有 `FONT_PYTHON` 指定解释器。服务器脚本通过 SSH 标准输入执行，使用 Python 标准库，无需安装额外服务。

目录交换是原子的，但不是跨多个 HTTP 请求的版本事务：已经打开的旧页面若后续请求旧资源，仍可能需要刷新。此次未额外构建旧资源兼容缓存机制。

## 测量与预估

基准使用当前完整 `dist`：602 个文件、56.56 MiB。压缩包 44.98 MiB，体积减少约 20.5%。

| 项目 | 原流程（上次正式发布） | 新流程（本地＋服务器隔离测试） |
|---|---:|---:|
| 构建链 | 约 30 秒 | 未改构建链，预估仍约 30 秒 |
| 本地打包 | 无 | 约 10.6 秒 |
| 远端预先清空 | 36.84 秒 | 无 |
| 上传 | 159.22 秒 | 约 3.7 秒 |
| 服务端校验、解压、首次备份与切换 | 包含在逐文件发布中 | 约 8.1–8.8 秒 |
| 完整 ship | 227.29 秒 | **推算约 55 秒** |

首次旧版备份占服务端处理约 5.5–5.8 秒；日后正常发布无需重复 bootstrap。真实目录交换约 1.6–1.9 毫秒，隔离回滚约 2.6–2.8 秒。

按本次观测，完整发布预计缩短约 76%，约为原来的四分之一；构建完成后的发布开销从约 197 秒降到约 24 秒。新流程尚未用于生产发布，因此 55 秒是基于分阶段实测的推算，不是已经执行的生产 ship 总耗时；网络、缓存、磁盘和站点规模会影响结果。
