# 主题头像过渡

最新的整套改动与云端 main 对比见 [合并前性能评估](./theme-avatar-performance.md)。下文 53 次绘制数据属于尚未加入浪头的历史预计算版本，不是最终波浪版的成本。

`profileConfig.themeAvatars` 指定亮暗两张图片。当前源文件保存在 `src/assets/images/theme-avatar/light.png` / `dark.png`（640×640），Astro 构建为最长边 512px、quality 80、保留透明度的 WebP。静态图和粒子纹理读取共享同一 WebP URL。保留原 `avatar` 用于未配置主题头像及 OG 等已有用途。具体体积与构建清理策略见 [图片优化](./image-optimization.md)。

## 实现与成本

- 静止状态为两个 CSS 按主题选择的 img，无 RAF、draw call 或逐粒子位置更新；原图透明度和清晰度保留。
- 自定义元素在初始延迟后的空闲时段解码、编译原生 WebGL shader 并上传两张 256×256 纹理。不引入 Three.js。未就绪时点击直接使用静态主题切换，避免阻塞圆形扩散。
- 桌面 128×128、移动 96×96 网格，空闲初始化时生成固定 UV、散开偏移、相位 sin/cos，上传一次 STATIC_DRAW buffer。每帧 CPU 只计算共享运动参数，shader 插值位置和颜色，无逐粒子三角函数和数组上传。浪头抵达头像之前复用初始画布；抵达后沿圆形边界后方做一次径向轻推和小幅回弹，重组前153ms内平滑淡出波浪，此后统一分支跳过波浪距离计算。每帧最多一个 draw call。像素为方形，聚合时完整覆盖。
- 画布仅头像大小，DPR 上限 2。静止保留 GPU 资源用于复用，页面元素移除时释放 context/buffer/program/texture；这不是零显存占用。
- 当前扩散为 560ms cubic-bezier(.22,.75,.18,1)。计算圆心到头像最远角点的距离，反解曲线得到完全扫过时间。扫过前只显示原头像的轻微散开像素，全部扫过后再运行 850ms 转换到目标头像。圆形扩散结束即解除全页 CSS 动画暂停；主题点击互斥保持到头像结束。
- 旧 root 截图保留完整静态头像、签名、遮罩。仅在 View Transition update 回调中为共同容器设置新命名层并启用 Canvas。新层用与 root 相同的圆心、半径、缓动及时钟裁剪：圆外是旧 root 原图，圆内是新主题下的粒子与遮罩。没有独立旧头像层，也不需要反向挖洞裁剪。避免旧截图捕获提前隐藏的图像或已清空的 WebGL buffer。
- WebGL 创建设置 failIfMajorPerformanceCaveat:true；浏览器判断存在严重性能问题时拒绝上下文，直接保留静态主题头像。此选项不是严格的 GPU 型号检测，不保证所有软件实现都被识别。
- 页面隐藏、滚动、resize、组件断开时取消粒子并恢复静态图；离屏、减少动态效果、WebGL 不可用或初始化失败时降级静态图。快速连点遵循原主题切换互斥机制。

## 验证与限制

两层圆形裁剪均使用各自截图盒的百分比圆心与归一化半径，并由 Web Animations 共享同一个 document.timeline 起始时间；不再混用 CSS 自动启动动画、像素裁剪和事后复制 currentTime。实际浏览器中纯像素参数在截图层出现尺度差异，已统一为百分比映射并检查中途弧线连续性。

Astro build 成功（44 页）。Astro check 仍有 52 个既有错误，本次文件无诊断。真实浏览器验证亮暗两向切换与 Swup 到 about 后继续切换成功。

1440×1000 本地一次无中途截图运行：抵达延迟 152ms，38 帧，帧间隔 P95 18.5ms、最大18.6ms，JS draw 提交平均 0.005ms。此值不包含 GPU 完成耗时，不是跨设备帧率承诺。截图会明显干扰测量；低端设备仍应以实际页面并行动画测试为准。DEV 下 `theme-avatar[data-last-run]` 可读取摘要；生产不采样帧间隔。

当前全局 CSS 只暂停 CSS animations/transitions，并不暂停其他组件的 JS RAF。这次避免扩展全局暂停机制，头像只在短暂过渡中运行。若后续增加重型背景 WebGL 或大面积 blur，应重新实测共用 GPU 的竞争。

## 2026-09-08 预计算优化评估

采用参数预计算而非整段动画逐帧缓存：运动仍是连续解析函数，不绑定帧率。利用 sin(a+b) 展开，把固定相位提前存入顶点属性。JS/GPU 随机哈希的浮点精度不同，因此具体颗粒路径会有差别，运动风格、时序和起终图保持不变。

| 指标 | 原实现 | 优化后 |
| --- | --- | --- |
| 桌面顶点缓冲 | 128 KiB | 384 KiB（增加 256 KiB） |
| 移动顶点缓冲 | 72 KiB | 216 KiB（增加 144 KiB） |
| 两张 256×256 RGBA 纹理 | 512 KiB | 512 KiB（不变，不含驱动开销） |
| 单次切换 draw calls | 70（69 个 RAF + capture） | 实测 53 |
| JS draw 路径平均耗时 | 0.014–0.028 ms | 0.010–0.022 ms |
| 帧间隔 P95 | 16.8–17.3 ms | 约 17.6 ms |

数据来自本机内置浏览器、1280×720、DPR 2、首页顶部、抵达延迟 314ms。替换新图片之后先测原 shader，得到 3 次完整运行；恢复任务后测最终优化，得到 4 次完整运行。采样期间不截图。不是同一时刻的严格 A/B，也不是低端设备测试，微小差别不能归因于优化。最终 4 次最大帧间隔均约 17.7ms。一次性路径预计算两次观察为 1.5 / 1.8ms（不含解码、编译和上传）；完成后的切换复用同一 buffer。

结论：此测试条件下确定减少约 24% 的头像 draw calls，并把固定粒子数学运算从每帧移到初始化；没有测出可确认的帧率提升。额外顶点读取带宽是其代价，不等于所有 GPU 都更快。JS draw 计时只测提交路径，不包含 GPU 完成时间；没有 GPU timer query 或能耗测量，不能声称 GPU 耗时/功耗下降某个百分比。页面级圆形截图、其他动画、纹理采样和混合成本不因预计算消失。

换图流程：替换 src/assets/images/theme-avatar 的同名源文件；生产环境重新 build/部署，生成带内容指纹的 WebP URL。预计算路径与图片内容无关，无需另生成离线数据。静态展示现在使用最长边 512px WebP，动画纹理仍为 256×256；没有增加粒子数量，也没有新增请求下载预计算文件。配置仍支持 public 绝对路径或远程 URL，但这两类不会自动转换为 WebP。
